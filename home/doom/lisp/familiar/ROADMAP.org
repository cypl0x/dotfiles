#+title: familiar: an Emacs-native AI harness, every protocol
#+startup: show2levels

The goal: one Emacs-native layer through which any model or agent works
with Emacs, and Emacs with any of them, over every protocol that matters.
Not another chat UI: the conversation is an Org buffer, tools are Emacs
itself, and the protocols are transports underneath.

Status as of 2026-11-04.  Survey of existing Elisp work: research report in
the JOURNAL entry of that day (repos, stars, last push, gaps).

* Order of work (each a self-contained step, tested and used live)

1. [X] MCP servers' tools in M-ß, opt-in per turn (=familiar-mcp-client.el=).
2. [X] Streamable-HTTP MCP server inside Emacs (=familiar-mcp-http.el=): no
   emacsclient wrapper, one port, token in a lock file like monet's;
   any agent on the machine attaches with a URL.
3. [~] Conversation core (=familiar-history.el=): one Org history of every turn (prompt, context,
   tool calls, result, cost) that M-ß, agent-shell transcripts and MCP
   sampling requests all write; Org as the storage format.
   Done: M-ß, familiar-request (OpenAI, Atuin, tasks).  Open: agent-shell
   transcripts, MCP sampling.
4. [ ] MCP sampling: servers that ask the client for a completion get one
   from familiar (budgeted, ledgered, asks first).
5. [ ] Emacs as an ACP agent: editors and tools speaking ACP drive a
   familiar conversation (the inverse of agent-shell).
6. [X] OpenAI-compatible endpoint: =/v1/chat/completions= served by Emacs (=familiar-openai.el=),
   so any tool that speaks it gets Emacs' tools and context.
7. [ ] A2A: agent card + task endpoints over the same HTTP server; an
   =@agent= keyword in M-ß to delegate to a remote A2A agent.
8. [ ] Split out: =familiar= as a standalone package (MELPA), Doom glue as a
   module.

Each step: research the current spec first (spec version, upstream
issues), batch tests without network, a live test in the lab frame, then
the README and journal.

* Introduction

This document is the complete guide to a modular Doom Emacs configuration
built for a specific workflow: dependently typed programming, knowledge
management, AI-assisted editing, remote development, and prose writing.

Every module is self-contained in its own =.el= file under =lisp/=.  Each
provides =use-package!= declarations, keybindings, transient menus, and
diagnostic commands.  The modules are loaded by =config.el= in dependency
order.

** Who is this for?

- Doom Emacs users who want a batteries-included configuration
- Developers working with proof assistants (Agda, Lean, Coq, Idris, F*)
- NixOS users who need Emacs tooling integrated with Nix
- Anyone who wants AI assistance embedded in their editor without context switches
- Writers who want distraction-free prose tools with spell checking and readability metrics

** Prerequisites

- GNU Emacs 30+ (pgtk build recommended for Wayland)
- Doom Emacs v2.2+
- NixOS or Nix package manager (for dependency management)
- A monospace font with ligature support (Maple Mono NF recommended)

** Quick Start

1. Run =~/.config/emacs/bin/doom sync= to install packages
2. Run =home-manager switch --flake ~/dotfiles= to install system dependencies
3. Restart Emacs daemon
4. Press =SPC H= to open the Feature Hub — the master transient menu

* Modules in Depth

** =+fonts.el= — Font Configuration and Ligatures
:PROPERTIES:
:CUSTOM_ID: fonts
:END:

*** Overview

Configures all five Doom font slots for Maple Mono NF and registers a
comprehensive ligature table.  Maple Mono NF v7.9 supports 130+ ligature
sequences via the =calt= (contextual alternates) OpenType feature.

*** Doom Font Slots

Doom provides five font variables.  This module sets all of them:

#+begin_src emacs-lisp
doom-font                ;; Default + fixed-pitch face
doom-big-font            ;; For presentations (doom-big-font-mode)
doom-variable-pitch-font ;; For mixed-pitch-mode in prose
doom-serif-font          ;; For fixed-pitch-serif face
doom-symbol-font         ;; Fallback for Unicode symbols (NO size!)
#+end_src

*Important:* Never set =:size= on =doom-symbol-font=.  It locks ALL symbol
rendering to that size.  The font cascade handles sizing automatically.

*** Ligatures: How They Work

Emacs renders ligatures through three layers:

1. *HarfBuzz* — the text shaping engine compiled into Emacs (pgtk).  It knows
   how to compose multi-character sequences into single glyphs IF the font has
   the appropriate OpenType lookup tables.

2. *=ligature.el=* — registers character sequences in Emacs'
   =composition-function-table=.  Without this registration, Emacs doesn't even
   attempt ligature composition.  Doom's =:ui ligatures= module loads this.

3. *The font itself* — Maple Mono NF stores ligature rules in its =calt=
   feature.  When HarfBuzz encounters a registered sequence, it queries the
   font's GSUB table and renders the ligature glyph.

*There are no font-specific ligature tables in Doom.* The same sequences are
sent to HarfBuzz regardless of font.  The font simply ignores sequences it
doesn't support.

*** Registered Ligature Sequences

This module registers 80+ sequences grouped by category:

| Category    | Examples                                      |   |        |     |         |
|-------------+-----------------------------------------------+---+--------+-----+---------|
| Arrows      | =->= ==>= =<-= =-->= ==>=>=                   |   |        |     |         |
| Equality    | ===== =!== ====== =!=== ==/==                 |   |        |     |         |
| Pipes       | =\vert>= =<\vert= =\vert\vert>= =<\vert\vert= |   |        |     |         |
| Logic       | =&&= =\vert\vert= =!!=                        |   |        |     |         |
| Haskell     | =::= =:::= =:== ==:==                         |   |        |     |         |
| Type theory | =\\/= =/\\= =<*>= =<+>=                       |   |        |     |         |
| Comments    | =//= =///= =/*= =*/= =/**=                    |   |        |     |         |
| Brackets    | ={                                            | = | \}= =[ | = = | ]= =#{= |
| Log badges  | =[TODO]= =[FIXME]= =[ERROR]= =[WARN]=         |   |        |     |         |

Log-level badges (=[TODO]=, =[DEBUG]=, etc.) are registered for =text-mode=
so they render in org files and logs.

** =+tramp.el= — Remote Editing Performance
:PROPERTIES:
:CUSTOM_ID: tramp
:END:

*** The Problem

Out of the box, Doom Emacs + TRAMP is unusably slow for remote editing.
Three issues compound:

1. *Wrong method*: Default =scp= opens a new SSH connection per file operation
2. *No multiplexing*: Each TRAMP operation = full SSH handshake
3. *eglot-ltex*: Hooks into =text-mode-hook= → tries to spawn =ltex-ls= on
   remote machine → blocks Emacs for 30 seconds

*** The Fix

This module applies six optimizations:

#+begin_src emacs-lisp
tramp-default-method    "ssh"   ;; Persistent shell, not per-file scp
tramp-use-connection-share nil  ;; Let ~/.ssh/config handle ControlMaster
tramp-verbose           1      ;; Errors only (default 3 = noisy)
remote-file-name-inhibit-cache 600 ;; Cache file attrs 10 min (default 10s)
remote-file-name-inhibit-locks t   ;; No lock files on remote
tramp-connection-timeout 10    ;; Fast timeout (SSH connects instantly)
#+end_src

Additionally:
- *VC disabled on remote*: Prevents =git status= probe on every file open
- *eglot blocked on remote*: =defadvice!= around =eglot-ensure= checks
  =file-remote-p= and skips for remote buffers
- *recentf excludes TRAMP*: No background stat-ing of remote files

*** SSH Configuration

The module expects =~/.ssh/config= to handle ControlMaster globally:

#+begin_src text
Host *
    ControlMaster auto
    ControlPath ~/.ssh/sockets/%r@%h-%p
    ControlPersist 600
    Compression yes
    ServerAliveInterval 30
#+end_src

This means one SSH handshake, then all subsequent operations multiplex over
the existing connection.  ControlPersist keeps the master alive for 10 minutes
after the last channel closes.

** =+prose.el= — Writing and Prose Tools
:PROPERTIES:
:CUSTOM_ID: prose
:END:

*** jinx: Fast Spell Checking

jinx uses the Enchant library (not Ispell/Hunspell directly).  It's faster
than flyspell because it uses overlays rather than the font-lock mechanism.

**** NixOS Setup

jinx compiles a native module (=jinx-mod.so=) on first use.  On NixOS, this
requires special handling because:

1. =pkg-config= is =pkgconf= on NixOS (different binary name)
2. Enchant headers live in a =-dev= store path not on =PKG_CONFIG_PATH=
3. =enchant-2.pc= has transitive glib deps that can't resolve without full
   dev closure

The module solves this by creating a shim =pkg-config= script at
=~/.local/bin/pkg-config= that returns direct =-I/-L/-l= flags pointing to
the nix store paths.  This shim is added to both =PATH= and =exec-path=.

**** Configuration

- Languages: =en_US de_DE= (English + German)
- Misspelling face: red wavy underline
- Safe wrapper: =+prose/jinx-mode-safe= catches compilation failure to prevent
  cascading errors that would disable font-lock

*** Writing Mode

=+prose/writing-mode= combines multiple settings for focused writing:

- Wide margins (8 columns each side)
- Increased line spacing
- No line numbers
- No highlight-line
- jinx enabled
- mixed-pitch enabled
- org-modern enabled (in org buffers)

Toggle: =SPC P w=

*** Reading Mode

=+prose/reading-mode= hides all diagnostic overlays:

- Disables flycheck, flymake, flyspell, jinx, sideline
- Disables eglot inlay hints
- Hides line numbers

Toggle: =SPC P r=

*** Text Statistics

=+prose/text-stats= (=SPC P s=) shows for buffer or region:

- Word count, character count (total + non-space)
- Line count, sentence count, paragraph count
- Reading time (~238 wpm), writing time (~40 wpm), speaking time (~150 wpm)

*** Word Frequency

=+prose/word-frequency= (=SPC P f=) shows top 100 most-used words with counts.

*** Readability Metrics

=+prose/readability= (=SPC P R=) calculates:

- *Flesch Reading Ease* (0-100, higher = easier)
- *Flesch-Kincaid Grade Level* (US grade equivalent)
- Human-readable grade description

*** Leo Translation Fix

=leo-translate-word= had broken umlaut rendering (ä ö ü displayed as garbage).
Root cause: leo.el's XML parser toggles multibyte twice (no-op) instead of
decoding UTF-8 after gzip decompression.

Fixed via =defadvice!= that intercepts =toggle-enable-multibyte-characters= calls
and replaces them with proper =decode-coding-region= + =set-buffer-multibyte=.

*** Spell Correction: Mouse + Keyboard

Misspelled words (red squiggly underline) can be corrected via:

- =RET= on the word (normal mode)
- Left-click on the word
- =SPC P j= (jinx-correct)
- =M-$= (flyspell-correct-at-point)

*** Architecture

1. *agent-shell* — Claude Code CLI via ACP protocol.  Uses Max subscription.

** =+prompt.el= — Emacs-Centric AI Prompt
:PROPERTIES:
:CUSTOM_ID: prompt
:END:

*** Philosophy

=+prompt= is the Emacs-centric counterpart to agent-shell's agent-centric approach.
Instead of switching to an agent buffer, you ask questions from wherever you are.
The AI can read your buffers, evaluate elisp, and insert text — all through
gptel's tool-use framework.

*** Context Expansion Syntax

When typing a prompt in the minibuffer, use =@= references to include context:

| Syntax         | Expands to                                    |
|----------------+-----------------------------------------------|
| =@buffer=      | Full content of current buffer                |
| =@region=      | Selected text (active region)                 |
| =@file:path=   | Content of file at path                       |
| =@var:name=    | Value of Emacs variable                       |
| =@eval:(expr)= | Result of evaluating elisp expression         |
| =@mode=        | Current major + minor modes                   |
| =@buffers=     | List of open file-visiting buffers with modes |

Example prompt: =@region Explain this Agda code and suggest improvements=

*** Tool-Use: LLM Reads/Writes Emacs

Eight tools are always enabled when using =+prompt/ask=:

| Tool                | What the LLM can do                   |
|---------------------+---------------------------------------|
| =read_buffer=       | Read any buffer's contents by name    |
| =list_buffers=      | See all open buffers with their modes |
| =eval_elisp=        | Evaluate arbitrary Emacs Lisp         |
| =describe_variable= | Get variable value + documentation    |
| =describe_function= | Get function documentation            |
| =insert_text=       | Insert text at cursor in any buffer   |
| =get_modes=         | Get active modes in a buffer          |
| =web_search=        | Search the web via Brave Search API   |

The LLM decides which tools to call based on your prompt.  If you ask
"what packages do I have loaded?", it will call =eval_elisp= with
=(length package-alist)= or similar.

** =+persist.el= — Persistent Scratch Buffers
:PROPERTIES:
:CUSTOM_ID: persist
:END:

*** The Problem

Emacs loses content of non-file-visiting buffers (=*scratch*=, =*new*=, etc.)
when the daemon restarts.  Sublime Text solved this in version 2 — every
buffer is auto-saved and restored, even unsaved ones.

*** How It Works

1. Every 60 seconds, all non-file-visiting buffers with content are saved
   to =~/.config/emacs/.local/cache/persist-buffers/=
2. On startup, persisted buffers are restored with their content and mode
3. When a persisted buffer is killed, its persistence file is removed
4. On =kill-emacs=, all buffers are saved one final time

*** Excluded Buffers

Internal buffers are excluded via pattern matching:

- =*Messages*=, =*Completions*=, =*Help*=, =*Compile*=
- =*Backtrace*=, =*Warnings*=, =*straight*=, =*doom*=
- Space-prefixed buffers (internal)
- =*Minibuf*=, =*Echo Area*=
- =*agent-shell*=, =*Claude*= (managed by agent-shell)

*** Manual Save

=SPC b P= — force-save all persistable buffers immediately.

** =+perf.el= — Measured Performance Fixes
:PROPERTIES:
:CUSTOM_ID: perf
:END:

Remote NixOS =/etc= files (store symlinks) froze Emacs: projectile listed all
of remote =/nix/store= and TRAMP merged it with a quadratic =seq-union=.
Projectile now skips the store, and =seq-union= on lists is linear.

** =+lsp-fallback.el= — LSP When the Server Exists
:PROPERTIES:
:CUSTOM_ID: lsp-fallback
:END:

A missing language server (e.g. no haskell-language-server) no longer makes
every buffer of that language report "[eglot] Searching for program: No such
file". The program is checked at connect time, after envrc applied the
project's environment, and if it's absent the buffer stays on tree-sitter,
flycheck and completion with one notice per session. =M-x eglot= is never
intercepted.

** =+monet.el= — Claude Code in Any Terminal Sees This Emacs
:PROPERTIES:
:CUSTOM_ID: monet
:END:

One monet session per project you visit, so Claude Code started in kitty
attaches automatically (=autoConnectIde=) and sees your selection and
diagnostics, and shows its edits as diffs in Emacs. The lock file's auth token
is enforced (monet itself never checks it); after a Claude exits the project
is offered again. =M-x monet-list-sessions=, =M-x +monet-auto-start-mode=.

:END:

* Troubleshooting

** Org-mode looks like fundamental mode (no colors)

Cause: jinx compilation failure cascading into font-lock death.

Fix: =M-: (global-font-lock-mode 1)= then revert buffer.

Prevention: =+prose/jinx-mode-safe= wraps jinx in =condition-case=.

** eglot timeout on startup

#+begin_example
[eglot] Timed out after 30 seconds
#+end_example

Cause: =eglot-ltex= trying to start =ltex-ls= for org/text buffers.

Fix: Already mitigated by =+tramp/eglot-ensure-no-remote= for remote.
For local: ltex-ls startup is slow (~5s) but should succeed if binary
is on PATH.

** SPC w / SPC s bindings wiped

Cause: =map!= with =(:prefix ("w" . "window"))= re-creates prefix, wiping
Doom's bindings.

Fix: Use =(:prefix "w")= (string only, no dotted pair).  Already fixed.

** gptel: authentication_error

Cause: Wrong model IDs.  API model names differ from Claude Code model names.

Fix: Use =claude-sonnet-4-6= not =claude-sonnet-4-20250514=.  Already fixed.

** jinx: Compilation of jinx-mod.so failed

Cause: NixOS — =pkg-config= not found, or enchant headers not on include path.

Fix: =+prose/jinx--setup-nix-env= creates shim script.  Ensure =enchant2= and
=pkg-config= in =emacs-deps.nix=.

* Keyboard Layout Notes

This configuration accounts for ISO QWERTZ DE keyboard layout.

Existing custom bindings using German keys:

| Key   | Command                   | Rationale                            |
|-------+---------------------------+--------------------------------------|
| =M-ö= | =previous-buffer=         | Buffer cycling on DE layout          |
| =M-ä= | =next-buffer=             | =ö/ä= replace =[/]= which need shift |
| =C-ö= | =doom/decrease-font-size= | Font resize on DE layout             |
| =C-ä= | =doom/increase-font-size= | =C-M-== is unreachable on QWERTZ     |

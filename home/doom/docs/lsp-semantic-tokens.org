#+title: LSP semantic tokens, here
#+date: 2026-11-05

Research note for the task list's "LSP semantic tokens" item: what the
protocol offers, what this Emacs does with it, which servers here use it.

* What semantic tokens are

A language server tells the editor what each identifier /is/ (a type, a
parameter, a mutable variable, a macro), not just what it looks like; the
editor paints it.  Each token has one type and any number of modifiers,
from a legend the server announces (LSP 3.16+).  Requests: the whole file,
a range, or the changes since last time; the server can ask the editor to
refresh.

* This Emacs

eglot (Emacs 32's) implements them: =eglot-semantic-tokens-mode= turns on
by itself in every buffer whose server offers them, asks for the visible
range, and repaints on the server's refresh requests.  Each standard token
type and modifier has a face =eglot-semantic-NAME= that inherits a
font-lock face, so themes work unchanged and tree-sitter's colours stay
underneath.  =M-x customize-group eglot-semantic-faces= lists them.

Added here (=lisp/+lsp-fallback.el=): faces for two modifiers servers add
beyond the standard ones, which eglot otherwise ignores:

| Modifier  | Face                     | Who sends it   | Looks        |
|-----------+--------------------------+----------------+--------------|
| =mutable= | =eglot-semantic-mutable= | rust-analyzer  | underlined   |
| =unsafe=  | =eglot-semantic-unsafe=  | rust-analyzer  | warning colour |
